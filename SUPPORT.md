# Support

The canonical support page for vmux Agent Console is
<https://imitation-alpha.github.io/vmux/support/>. Email
[support@imitationalpha.com](mailto:support@imitationalpha.com) for direct
support. Support is provided on a best-effort basis, without a response-time or
resolution-time SLA.

## Where to ask

For non-sensitive reports, the repository's
[issue chooser](https://github.com/imitation-alpha/vmux/issues/new/choose) is an
optional public channel:

- **Bug report** when vmux behaves incorrectly and you can describe how to
  reproduce it.
- **Feature proposal** for a new capability or a change to documented behavior.
  Significant features need maintainer acceptance before implementation.
- **Question / support** when you need help configuring or using existing
  behavior.

GitHub Issues are public and searchable. Redact bearer tokens, API keys, APNs
credentials, private repository names, hostnames, IP addresses when sensitive,
and confidential pane or log contents. Use a minimal dummy example whenever
possible.

Before opening an issue:

1. Check the [documentation](https://imitation-alpha.github.io/vmux/), existing
   issues, and the latest [changelog](CHANGELOG.md).
2. Upgrade to the latest release when practical.
3. Record your vmux version, installation source, operating system, Python and
   tmux versions, coding agent, browser/client, attempted steps, and redacted
   output.
4. Reduce the problem to the smallest reproducible sequence you can.

Maintainers may convert an issue to the appropriate category, ask for a minimal
reproduction, close duplicates, or close reports that cannot be investigated
without the requested information.

## Security and conduct

Suspected vulnerabilities must never be filed publicly. Follow the private
reporting process in [SECURITY.md](SECURITY.md).

Community conduct is governed by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
